LangChain学习笔记

概述 Overview

定位

LangChain 是快速构建基于 LLM 的智能代理和 LLM 应用的框架。不到 10 行代码即可连接 OpenAI、Anthropic、Google 等主流模型提供商。LangChain 提供预构建的代理架构和模型集成，帮助开发者快速启动并无缝将 LLM 集成到应用中。

底层依赖

LangChain 的代理构建在 LangGraph 图运行时之上。LangGraph 是 LangChain 团队提供的低级代理编排框架和运行时，支持持久化执行、流式处理、人在回路、数据持久化等功能。基础使用无需了解 LangGraph，但当需要更复杂的流程控制时，可以直接使用 LangGraph。

版本说明

LangChain v1.0 已正式发布，带来两项重大变更：

  1. 完全重构了所有 chains 和 agents，统一替换为基于 LangGraph 构建的 Agent 抽象
  2. 标准化了消息内容格式，支持推理块、引用、服务器端工具调用等复杂输出类型

对于仍使用旧版 chains/agents 且不想升级的用户，可安装 langchain-classic 包继续使用旧版本。

核心优势

优势 说明
标准模型接口 不同提供商有各自独特的 API 和响应格式，LangChain 标准化了模型交互方式，使开发者可以无缝切换提供商，避免供应商锁定
易用且灵活的代理 10 行代码即可创建简单代理，同时也支持复杂的上下文管理和自定义操作
构建于 LangGraph 之上 继承 LangGraph 的持久执行、人在回路、数据持久化等能力
LangSmith 可观测调试 提供可视化工具，跟踪执行路径、状态转换并生成详细运行时指标

使用场景

  • 需要快速构建 LLM 智能代理和应用
  • 需要在不同模型提供商之间灵活切换
  • 需要代理具备工具调用、记忆、流式输出等能力
  • 需要对代理行为进行可观测、调试和评估

注意事项

  • LangChain v1.0 与 v0.x 存在重大变更，升级前需参考迁移指南
  • 基础使用无需了解 LangGraph，但高级定制需要掌握 LangGraph 概念
  • 当需要更复杂的确定性工作流和精确延迟控制时，应直接使用 LangGraph

设计理念 Philosophy

两大核心目标

目标一：让开发者便捷使用各类最优大模型

不同提供商暴露不同的 API、模型参数和消息格式。标准化这些模型的输入和输出是核心重点，使开发者能够轻松切换到最新、最先进的模型，避免被锁定。

目标二：简化编排复杂流程，对接外部数据与计算

模型不应仅用于文本生成，还应被用于编排与其他数据交互的更复杂流程。LangChain 让定义 LLM 可动态使用的工具变得容易，并帮助解析和访问非结构化数据。

核心组件 Core

Agents 智能体

概念说明

智能体将语言模型与工具结合，创建能够对任务进行推理、决定使用哪些工具并迭代寻求解决方案的系统。create_agent() 是 LangChain v1 中创建智能体的唯一入口，底层基于 LangGraph 构建图运行时。

智能体在循环中运行工具以实现目标，会一直运行直到满足停止条件——即模型输出最终结果或达到迭代次数限制。

使用场景

  • 需要自主推理并调用外部工具完成任务
  • 需要结合多个工具和数据源进行复杂决策
  • 需要支持记忆、流式输出、人在回路等高级功能

Short-term-Memory 短期记忆

概念说明

短期记忆让应用程序能够记住单个线程或对话中的先前交互。会话历史记录是短期记忆最常见的形式。短期记忆存储在 checkpointer（检查点）中，与长期记忆（Store）不同，短期记忆的作用范围是单个会话线程。

使用场景

Middleware 中间件

概念说明

中间件提供了一种方法，可以更精细地控制代理内部的执行流程。核心代理循环包括调用模型、让模型选择并执行工具、在模型不再调用工具时结束。中间件可以监控、修改、控制代理全生命周期执行。

使用场景

Structured-output 结构化输出

概念说明

结构化输出允许智能体以特定的、可预测的格式返回数据。用户设置所需的结构化输出模式，当模型生成结构化数据时，它会被捕获、验证，并作为智能体状态中 'structured_response' 键的值返回。

使用场景

  • 需要从非结构化文本中提取结构化数据
  • 需要确保输出符合特定模式以供下游系统使用
  • 需要对输出进行类型验证和约束

两种策略

ProviderStrategy：模型原生结构化输出

使用提供商原生结构化输出功能（如 OpenAI 的 JSON mode）。

ToolStrategy：基于工具调用模拟结构化输出

使用工具调用机制实现结构化输出，适用于不支持原生结构化输出的模型。

策略对比

维度 ProviderStrategy ToolStrategy
实现方式 模型原生结构化输出功能 基于工具调用模拟
模型支持 OpenAI、Grok 等原生支持的模型 所有支持工具调用的模型
可靠性 高（原生支持） 中（依赖工具调用）
灵活性 低（受限于模型能力） 高（可自定义工具消息内容、错误处理）
自定义 不支持 支持自定义工具消息内容和错误处理

概念说明

守卫通过在智能体执行的关键点验证和过滤内容，帮助构建安全、合规的 AI 应用。它们可以在问题发生前检测敏感信息、强制执行内容策略、验证输出并防止不安全行为。守卫通过中间件实现，在策略性节点拦截执行。

使用场景

  • 防止 PII（个人身份信息）泄露
  • 检测和阻止提示注入攻击
  • 阻止不当或有害内容
  • 强制执行业务规则和合规要求
  • 验证输出质量和准确性

两类守卫

方法 描述 优点 缺点
确定性守卫 使用基于规则的逻辑，如正则表达式、关键词匹配或明确检查 快速、可预测、经济高效 可能会错过细微的违规行为
基于模型的守卫 使用 LLM 或分类器通过语义理解评估内容 可以捕获规则遗漏的微妙问题 速度较慢且成本较高

概念说明

LangChain 的 create_agent 在 LangGraph 的运行时环境下运行。LangGraph 暴露了一个 Runtime 对象，包含运行时的上下文信息。Runtime 对象提供三个核心能力：静态配置、长期记忆和自定义流式输出。

store 长期记忆持久存储 跨会话 用户偏好、历史数据
stream_writer 自定义流式输出 单次调用 工具执行进度

Context-engineering 上下文工程

概念说明

构建代理的难点在于使其足够可靠。当代理失败时，通常是因为代理内部的 LLM 调用采取了错误的行动或没有达到预期。LLM 失败的原因有两个：底层 LLM 能力不足，或没有将正确的上下文传递给 LLM。通常情况下，代理不可靠的首要原因是后者。

上下文工程就是以正确的格式提供正确的信息和工具，以便 LLM 能够完成任务。这是 AI 工程师的核心工作。

三大上下文

上下文类型 控制内容 瞬态/持久
模型上下文 进入模型调用的内容（指令、消息历史、工具、响应格式） 瞬态
工具上下文 工具可以访问和产生的内容（对状态、存储、运行时上下文的读/写） 持久
生命周期上下文 模型调用和工具调用之间发生的内容（摘要、安全防护、日志等） 持久

三类数据源

数据源 别名 范围 示例
Runtime Context 静态配置 会话范围 用户 ID、API 密钥、数据库连接、权限
State 短期记忆 会话范围 当前消息、已上传文件、认证状态、工具结果
Store 长期记忆 跨会话 用户偏好、提取的见解、历史数据

模型上下文

模型上下文控制每次模型调用中包含的内容。

MCP 模型上下文协议

概念说明

模型上下文协议（MCP）是一种开放协议，标准化了应用程序如何向 LLM 提供工具和上下文。LangChain 代理可以使用 langchain-mcp-adapters 库来使用在 MCP 服务器上定义的工具。

使用场景

  • 需要标准化方式调用外部工具
  • 需要连接多个工具服务器
  • 需要支持本地或远程工具调用

传输方式

传输方式 说明 适用场景
stdio 客户端将服务器作为子进程启动，通过标准输入/输出通信 本地工具、简单设置
streamable-http 服务器作为独立进程运行，处理 HTTP 请求 远程连接、多客户端
SSE Streamable HTTP 的变体，针对实时流式通信优化 实时流式通信

Human-in-the-loop 人在回路

概念说明

人在回路（HITL）中间件允许在代理工具调用中添加人工监督。当模型提出可能需要人工审查的操作时，中间件会暂停执行并等待决策。它通过对照可配置的策略检查每个工具调用来实现，需要工具调用匹配策略时发出中断来停止执行，图的状态通过 LangGraph 的持久化层保存。

依赖：checkpointer 检查点持久化

注意事项：必须配置一个检查点来在中断时持久化图状态。生产环境请使用持久性检查点，如 AsyncPostgresSaver。

三种人工决策

决策类型 描述 示例用例
approve 操作按原样批准并执行，不进行任何更改 完全按照草稿发送电子邮件
edit 工具调用经过修改后执行 在发送电子邮件前更改收件人
reject 工具调用被拒绝，并将解释添加到对话中 拒绝电子邮件草稿并解释如何重写
approve 批准
edit 编辑

注意事项：编辑工具参数时请保守进行更改。对原始参数进行重大修改可能导致模型重新评估其方法，可能多次执行工具或采取意外操作。

reject 拒绝并反馈

message 会作为反馈添加到对话中，帮助代理理解操作被拒绝的原因以及它应该做什么。

Multi-agent 多智能体系统

概念说明

多智能体系统将复杂的应用拆分成多个协同工作的专业化智能体。不依赖单个智能体处理每一步，而是将更小、更专注的智能体组合成一个协调的工作流程。

使用场景

  • 单个智能体拥有太多工具，导致难以决定使用哪个工具
  • 上下文或记忆对于单个智能体来说过于庞大
  • 任务需要专业化（如规划者、研究员、数学专家）

两种架构模式

模式 工作原理 控制流 示例用例
工具调用模式 主管智能体将其他智能体作为工具调用，子智能体不直接与用户交谈 集中式 任务编排、结构化工作流程
交接模式 当前智能体决定将控制权转移给另一个智能体，用户可与新智能体直接交互 分散式 多领域对话、专家接管

模式选择对比

问题 工具调用 交接
需要集中式控制？ 是 否
希望智能体直接与用户交互？ 否 是
需要复杂的多专家对话？ 有限 强

注意事项：可以混合使用两种模式，使用交接进行智能体切换，并让每个智能体调用子智能体作为工具。

上下文工程

多智能体设计的核心是上下文工程——决定每个智能体看到哪些信息。LangChain 允许精细控制：

  • 传递给每个智能体的对话或状态的部分
  • 为子智能体量身定制的专业提示
  • 包含/排除中间推理
  • 为每个智能体定制输入/输出格式

注意事项：系统质量严重依赖于上下文工程。目标是确保每个智能体都能访问执行其任务所需的正确数据。

Retrieval 检索 & RAG

概念说明

大型语言模型有两个主要局限：有限的上下文（无法一次性消化整个语料库）和静态的知识（训练数据固定在某个时间点）。检索通过在查询时获取相关的外部知识来解决这些问题，这是检索增强生成（RAG）的基础。

检索流水线组件

构成要素

组件 描述
文档加载器 从外部源摄取数据，返回标准化的 Document 对象
文本切分器 将大文档拆分成更小的块，适应模型的上下文窗口
嵌入模型 将文本转化为数字向量，使含义相似的文本在向量空间中靠近
向量存储 用于存储和搜索嵌入的专用数据库
检索器 给定非结构化查询，返回文档的接口

三种 RAG 架构

架构 描述 控制 灵活性 延迟 示例用例
2-step RAG 检索总在生成之前，简单可预测 高 低 快 FAQ、文档机器人
Agentic RAG LLM 驱动的智能体决定何时如何检索 低 高 可变 研究助理
Hybrid RAG 结合两种方法特点，带验证步骤 中 中 可变 带质量验证的领域问答
2-step RAG

检索步骤总是在生成步骤之前执行，简单直接且可预测。

Agentic RAG 智能体式 RAG

智能体逐步推理，决定何时以及如何检索信息。智能体实现 RAG 行为只需要访问一个或多个可以获取外部知识的工具。

Hybrid 混合 RAG

结合 2-step RAG 和 Agentic RAG 的特点，引入中间步骤：

  • 查询增强：修改输入问题以提高检索质量
  • 检索验证：评估检索到的文档是否相关和充分
  • 答案验证：检查生成答案的准确性和完整性

Long-term-memory 长期记忆

概念说明

LangChain 智能体使用 LangGraph 持久化实现长期记忆。长期记忆作为 JSON 文档存储在 Store 中，与短期记忆（checkpointer）不同，长期记忆的作用范围是跨会话的。

基于 LangGraph Store 持久存储

每条记忆都组织在一个自定义的 namespace（命名空间，类似于文件夹）和一个独特的 key（键，类似于文件名）下。这种结构支持记忆的层次化组织，可以通过内容过滤器支持跨命名空间搜索。

namespace 命名空间 + key 键

InMemoryStore 内存实现

注意事项：生产环境应使用基于数据库的存储。

LangSmith

概念说明

LangSmith 是 LangChain 团队推出的闭源平台，提供可观测性和评估工具。构建 Agent 的主要问题在于可靠性，LangSmith 正是为解决该需求而构建的。LangChain 与 LangSmith 无缝集成，提供可视化工具跟踪执行路径、状态转换并生成详细运行时指标。

使用场景

  • 跟踪代理执行路径和状态转换
  • 调试代理行为和工具调用
  • 评估代理和 RAG 系统的性能
  • 监控生产环境中的代理运行

核心能力

能力 说明
可观测性 可视化跟踪执行路径、状态转换，生成详细运行时指标
调试 帮助定位代理行为中的问题，查看每一步的输入输出
评估 提供评估工具和框架，量化代理和 RAG 的性能
监控 生产环境中的实时监控和告警

使用方式

注意事项

  • LangSmith 是闭源平台，需要注册账号
  • 生产环境使用时注意数据隐私和合规
  • 跟踪会增加少量延迟，但通常可以忽略不计
  • 评估功能需要定义评估数据集和评估指标

LangGraph

概念说明

LangGraph 是 LangChain 团队推出的开源低级代理编排框架和运行时。它提供了图运行时，支持持久化执行、流式输出、短期记忆、人在回路等功能。LangChain 的代理构建在 LangGraph 之上，基础使用无需了解 LangGraph，但高级定制需要掌握其概念。

使用场景

  • 需要比 LangChain Agent 抽象更精细的流程控制
  • 需要结合确定性与智能工作流
  • 需要高度自定义和精确延迟控制
  • 需要构建复杂的多步骤、多条件分支的代理系统

核心能力

能力 说明
图编排 通过节点（步骤）和边（连接）定义代理执行流程
持久化执行 通过 checkpointer 检查点机制保存执行状态
短期记忆 通过 checkpointer 维护会话内的消息历史和状态
长期记忆 通过 Store 机制实现跨会话的持久化存储
流式输出 支持多种流式传输模式
人在回路 支持中断和恢复执行
多智能体编排 支持构建多智能体协作系统

LangGraph 与 LangChain 关系

维度 LangChain LangGraph
定位 高层代理抽象 低级编排框架
复杂度 低（快速上手） 高（精细控制）
基础使用 无需了解 LangGraph -
高级定制 通过中间件和配置 直接使用 LangGraph API
Agent 实现 create_agent 图运行时

底层基础设施

checkpointer 检查点

检查点是 LangGraph 的持久化机制，用于保存代理执行状态。短期记忆和人在回路都依赖检查点。

Store 存储

Store 是 LangGraph 的长期记忆持久存储机制，用于跨会话的数据持久化。

注意事项

  • LangGraph 是 LangChain 的底层依赖，但也可以独立使用
  • 当 LangChain 的高级抽象无法满足需求时，可以直接使用 LangGraph
  • LangGraph 需要更深入的理解图编排概念
  • 生产环境务必使用持久化的检查点和存储方案
