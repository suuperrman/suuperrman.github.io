JVM学习笔记

第一部分 基础篇

一、JVM入门

1.1 JVM虚拟机导论

JVM（Java Virtual Machine）是Java虚拟机的简称，是一台虚构的计算机，通过在实际计算机上软件模拟来运行Java字节码。JVM是Java平台无关性的基石，也是Java语言”一次编译，到处运行”的核心支撑。

概念说明：JVM不是一台真实的物理机器，而是一个运行在操作系统上的进程。它有自己的指令集、寄存器组、栈、堆、方法区等”硬件”结构，通过软件方式模拟实现。

使用场景：

  • 运行Java应用程序（Java SE/EE程序）
  • 运行其他JVM语言（Kotlin、Scala、Groovy等编译生成的字节码）
  • 嵌入式设备、服务器、云端容器化部署

注意事项：JVM本身是平台相关的，不同操作系统（Windows、Linux、macOS）有不同的JVM实现，但它们都能运行相同的字节码文件（.class）。

1.2 初识JVM

Java程序的执行流程：源代码（.java） -> 编译器（javac） -> 字节码（.class） -> 类加载器 -> 运行时数据区 -> 执行引擎 -> 操作系统硬件。

HotSpot VM：Oracle JDK和OpenJDK中最主流的JVM实现，由Longview Technologies公司开发，后被Sun Microsystems收购。它集成了解释器和JIT编译器（即时编译器），采用分层编译策略。

1.3 Java虚拟机整体组成

JVM由以下三大子系统组成：

  1. 类加载子系统：负责从文件系统、网络等来源加载字节码文件，经过加载、连接、初始化三个阶段将类信息放入方法区。
  2. 运行时数据区：JVM在运行期间管理的内存区域，包括程序计数器、Java虚拟机栈、本地方法栈、堆、方法区（元空间）。
  3. 执行引擎：负责执行字节码指令，包括解释器、JIT编译器和垃圾回收器。

二、字节码文件

2.1 字节码文件基础信息

字节码文件（.class）是Java编译器（javac）将源代码编译后生成的二进制文件，是JVM执行的基本单元。

概念说明：字节码文件采用紧凑的二进制格式存储，不依赖任何操作系统和硬件平台。一个.class文件中包含魔数、版本号、常量池、访问标志、类/父类/接口信息、字段表、方法表、属性表等。

编译后使用javap -verbose BytecodeDemo.class可以查看字节码详细信息：

字节码文件结构：

组成部分 说明
魔数（Magic Number） 4字节，固定为0xCAFEBABE，标识这是class文件
版本号 minor_version + major_version，标识JDK版本
常量池 存放字面量和符号引用

2.2 常量池和方法

常量池是字节码文件中最重要的数据结构之一，存放编译期已知的字面量（如字符串、final常量）和符号引用（如类名、方法名、字段名的引用）。

方法表存储类中每个方法的描述信息，包括方法名、描述符（参数和返回值类型）、访问标志、字节码指令、异常表等。

三、类加载子系统

3.1 类的生命周期

类的生命周期从加载到JVM内存开始，到卸载出内存结束，共经历七个阶段：加载、验证、准备、解析、初始化、使用、卸载。其中验证、准备、解析三个阶段合称为连接。

加载阶段

JVM通过类的全限定名获取定义此类的二进制字节流，将字节流转换为方法区的运行时数据结构，在堆中生成该类的Class对象，作为方法区数据的访问入口。

连接阶段

连接阶段包含三个子阶段：

  1. 验证：确保class文件字节流符合JVM规范，包括文件格式验证、元数据验证、字节码验证、符号引用验证。
  2. 准备：为静态变量分配内存并设置零值（如int为0，引用为null）。final static修饰的常量在此阶段直接赋初始值。
  3. 解析：将常量池中的符号引用替换为直接引用（内存地址或偏移量）。

初始化阶段

执行类构造器<clinit>()方法，为静态变量赋值并执行静态代码块。<clinit>()由编译器自动收集所有静态变量赋值语句和静态代码块合并产生。

注意事项：

  • <clinit>()方法由JVM保证线程安全（加锁），多线程下类只被初始化一次
  • 接口中没有静态代码块，但可以有默认方法，接口的<clinit>不需要加锁
  • 不会触发初始化的场景：通过子类引用父类静态字段、通过数组定义类引用、调用final常量

3.3 双亲委派机制

双亲委派工作流程

当一个类加载器收到类加载请求时，首先不会自己尝试加载，而是将请求委托给父类加载器，父类加载器再向上委托，直到最顶层的启动类加载器。只有父类加载器无法完成加载时，子类加载器才会尝试自己加载。

双亲委派的意义：

  • 安全性：防止核心类被篡改（自定义java.lang.String不会被加载）
  • 唯一性：保证同一个类只会被加载一次，避免重复加载

打破双亲委派机制

自定义类加载器

通过继承ClassLoader并重写findClass方法实现自定义加载逻辑。如果需要完全打破双亲委派，可以重写loadClass方法。

线程上下文类加载器

线程上下文类加载器（Thread Context ClassLoader）用于解决双亲委派模型无法满足的场景，如SPI机制。父类加载器可以通过线程上下文类加载器访问子类加载器的类。

OSGi热部署

OSGi（Open Services Gateway initiative）采用网状类加载结构，每个模块（Bundle）有独立的类加载器，可以实现模块级别的热部署和热卸载。OSGi不遵循标准的双亲委派模型，而是根据模块间的依赖关系进行类加载。

注意事项：打破双亲委派可能导致类加载混乱，非必要不打破。Tomcat、Spring Boot等框架根据自身需求设计了特殊的类加载策略。

四、运行时数据区

运行时数据区是JVM在运行期间管理的内存区域，分为线程私有和线程共享两大类。

4.1 程序计数器

程序计数器（Program Counter Register）是一块较小的内存区域，记录当前线程正在执行的字节码行号。每个线程独有，生命周期与线程相同。

注意事项：程序计数器是唯一不会发生OutOfMemoryError的内存区域。线程切换后恢复时，依赖PC寄存器恢复到正确的执行位置。

4.2 Java栈

Java虚拟机栈（Java VM Stack）是每个线程私有的内存区域，描述Java方法执行的内存模型。每个方法执行时创建一个栈帧（Stack Frame），方法结束时栈帧出栈。

局部变量表

局部变量表是方法参数和方法内部局部变量的存储空间，以变量槽（Slot）为最小单位。每个Slot可以存放boolean、byte、char、short、int、float、引用类型或returnAddress（64位的long和double占两个Slot）。

操作数栈、帧数据

操作数栈：方法执行过程中的工作空间，用于存放计算过程中的中间结果。字节码指令通过压栈和出栈操作数据。

帧数据：包含动态链接（指向运行时常量池中该方法的引用，支持动态绑定）和方法返回地址（方法结束后恢复到调用者的执行位置）。

栈内存溢出

当栈深度超过JVM允许的最大深度时，抛出StackOverflowError。当无法分配新的栈帧时，抛出OutOfMemoryError。

注意事项：通过-Xss参数调整栈大小。栈越大递归深度越大，但能创建的线程数越少（总内存有限）。栈深度不是可预估的，取决于方法栈帧大小。

4.3 堆内存

堆是JVM管理的最大一块内存区域，所有线程共享，在JVM启动时创建。堆用于存储几乎所有的对象实例和数组，是垃圾回收的主要区域。

堆内存分代结构（JDK 8）：

  • 新生代（Young Generation）：Eden区 + Survivor0 + Survivor1，比例8:1:1，存放新创建的对象
  • 老年代（Old Generation）：存放经过多次GC仍存活的对象和大对象

注意事项：

  • -Xms设置初始堆大小，-Xmx设置最大堆大小，生产环境建议两者设为相同值以避免频繁扩容
  • -Xmn设置新生代大小，-XX:NewRatio设置新生代与老年代比例（默认2，即1:2）
  • -XX:SurvivorRatio设置Eden与Survivor比例（默认8）
  • 大对象（超过-XX:PretenureSizeThreshold）直接进入老年代

4.4 方法区

方法区是各个线程共享的内存区域，用于存储已被加载的类信息、常量、静态变量、即时编译后的代码缓存等数据。

字符串常量池

字符串常量池是方法区的一部分，用于存储字符串字面量，避免重复创建相同内容的字符串对象。

注意事项：JDK 7将字符串常量池从永久代移到堆中，是为了在Full GC时能回收不再使用的字符串，避免永久代OOM。

方法区内存回收

方法区的回收条件较为苛刻，主要回收以下内容：

  • 废弃常量（无任何引用的常量）
  • 不再使用的类型（同时满足三个条件：该类所有实例已被回收、加载该类的类加载器已被回收、该类的Class对象没有任何引用）

4.5 直接内存

直接内存（Direct Memory）不属于JVM运行时数据区，而是使用Native函数直接分配堆外内存。通过NIO的ByteBuffer.allocateDirect()分配，避免了Java堆和Native堆之间的数据拷贝，提高IO效率。

堆内存 vs 直接内存 对比说明：

维度 堆内存（Heap） 直接内存（Direct Memory）
分配方式 ByteBuffer.allocate ByteBuffer.allocateDirect
受GC管理 是 不直接受GC管理（通过Cleaner释放）
IO性能 需要额外拷贝 零拷贝，性能高
内存限制 -Xmx -XX:MaxDirectMemorySize
适用场景 普通数据存储 大文件IO、网络通信

注意事项：直接内存的释放不立即生效，可能导致内存占用看起来偏高。不当使用可能造成内存泄漏。Netty等网络框架大量使用直接内存提升性能。

五、垃圾回收GC

5.1 自动垃圾回收

垃圾回收（Garbage Collection）是JVM自动释放不再被引用的对象所占用的内存的机制，无需程序员手动释放。

注意事项：不要在代码中频繁调用System.gc()，这会触发Full GC导致停顿。让JVM自行决定GC时机。

5.2 判断对象存活

引用计数法

给对象添加一个引用计数器，有引用时加1，引用失效时减1，为0则可回收。

引用计数法缺陷：无法解决循环引用问题。主流JVM不采用此方法。

可达性分析法

以GC Roots为起点，从这些节点向下搜索，搜索走过的路径称为引用链。如果一个对象到GC Roots没有任何引用链相连，则该对象不可达，可以被回收。

GC Roots包括：

  1. 虚拟机栈中引用的对象（方法参数、局部变量）
  2. 方法区中静态属性引用的对象
  3. 方法区中常量引用的对象
  4. 本地方法栈中JNI引用的对象
  5. 被同步锁（synchronized）持有的对象
  6. JVM内部引用（基本类型对应的Class对象、常驻异常对象、系统类加载器）
  7. JMXBean、JVMTI等JVM内部注册的对象

5.3 四大引用

Java将引用分为强、软、弱、虚四种，强度依次递减，以便在不同场景下灵活控制对象的生命周期。

四大引用对比说明：

引用类型 回收时机 get()返回值 典型应用场景
强引用 永不回收（即使OOM） 对象本身 普通对象引用
软引用 内存不足时 对象或null 缓存（图片、网页）
弱引用 下一次GC时 对象或null ThreadLocal、WeakHashMap
虚引用 随时可回收 null（始终） 资源清理通知、直接内存释放

5.4 GC算法评价标准

  • 吞吐量：用户代码运行时间占总运行时间的比例（吞吐量 = 用户时间 / (用户时间 + GC时间)）
  • 停顿时间：GC时暂停应用线程的时间（STW, Stop The World）
  • GC频率：GC执行的频率，频率越低对应用影响越小
  • 内存占用：GC运行需要的额外内存开销
  • 碎片：内存碎片程度，碎片过多会导致分配失败

5.5 GC算法

标记清除

标记存活对象，清除未标记（垃圾）对象。

优点：实现简单。缺点：产生内存碎片，分配大对象时可能失败。

标记复制

将内存分为两块，每次只用一块，GC时将存活对象复制到另一块，然后清除当前块。

优点：无内存碎片，分配快。缺点：浪费一半内存空间。适用于新生代（存活对象少）。

标记整理

标记存活对象后，将存活对象向内存一端移动，清除边界以外的空间。

优点：无碎片，不浪费内存。缺点：移动对象开销大，需要更新引用。适用于老年代。

分代GC

将堆分为新生代和老年代，根据对象存活特点使用不同算法。

GC算法对比说明：

算法 优点 缺点 适用区域
标记清除 实现简单 内存碎片 老年代（CMS）
标记复制 无碎片 浪费一半内存 新生代
标记整理 无碎片无浪费 移动开销大 老年代
分代GC 综合最优 实现复杂 整个堆

5.6 垃圾回收器

Serial收集器

单线程收集器，进行GC时暂停所有用户线程（STW）。新生代使用标记复制，老年代使用标记整理。

适用场景：客户端模式、小内存应用。

Parallel收集器

多线程收集器，注重吞吐量。新生代使用标记复制（Parallel Scavenge），老年代使用标记整理（Parallel Old）。

适用场景：注重吞吐量的后台计算任务、批处理应用。JDK 8默认收集器。

CMS收集器

Concurrent Mark Sweep，以获取最短回收停顿时间为目标的收集器。使用标记清除算法，分为四个阶段：

适用场景：注重响应速度的互联网应用、B/S架构系统。

注意事项：CMS在JDK 9被标记为废弃，JDK 14中被移除，推荐使用G1。

G1收集器

Garbage First，面向大堆内存的收集器。将堆划分为多个大小相等的Region（1MB~32MB），每个Region可以动态充当Eden、Survivor、Old或Humongous区域。

三、GC调优

3.1 GC调优核心目标

  • 降低停顿时间：减少STW（Stop The World）时间，提升用户体验

  • 控制GC频率：减少GC触发次数

第四部分 原理篇

一、对象内存存储：栈上分配、堆上存储

栈上分配

JIT编译器通过逃逸分析（Escape Analysis），如果判断对象不会逃逸出方法（不会被外部引用），则直接在栈上分配，避免堆内存分配和GC开销。

逃逸分析的结果可以优化三种方式：

  • 栈上分配：对象不逃逸则分配在栈上
  • 标量替换：将对象拆解为基础类型，不创建对象
  • 同步消除：对象不逃逸则消除synchronized

二、方法调用原理：静态绑定、动态绑定

静态绑定

在编译期就确定方法的调用目标，直接指向方法入口地址。适用于final方法、静态方法、private方法。

动态绑定

在运行期根据对象的实际类型确定方法调用目标，是实现多态的基础。JVM通过虚方法表（vtable）实现动态绑定。

虚方法表（vtable）原理：每个类在方法区维护一个虚方法表，表中存放各方法的实际入口地址。子类如果重写了父类方法，虚方法表中对应槽位指向子类的方法入口。invokevirtual通过对象头中的类型指针找到Class元数据，再查虚方法表确定方法入口。

静态绑定 vs 动态绑定 对比说明：

维度 静态绑定 动态绑定
确定时机 编译期 运行期
字节码指令 invokespecial / invokestatic invokevirtual / invokeinterface
适用方法 final、static、private、构造方法 普通实例方法
多态 不支持 支持
性能 更快 略慢（查虚方法表）

三、JIT即时编译器原理与优化

JIT原理

JVM采用解释器 + JIT编译器的混合模式运行。解释器逐行解释执行字节码，JIT将热点代码编译为本地机器码后直接执行。

JIT优化技术

分层编译

JDK 8引入分层编译，将编译分为五个层次：

层级 说明
层级0 解释执行
层级1 C1编译，无profiling（快速编译，简单优化）
层级2 C1编译，带方法调用和循环回边计数
层级3 C1编译，完整profiling
层级4 C2编译，激进优化

先由C1快速编译提升性能，收集profiling数据后，C2进行激进优化，达到最高性能。

四、G1 / ZGC / ShenandoahGC底层实现原理

G1底层实现

G1的Remembered Set：每个Region维护一个RSet，记录哪些其他Region的对象引用了本Region的对象。通过RSet可以只扫描相关Region而非全堆，实现精准回收。

ZGC底层实现

ZGC的核心技术是染色指针，利用64位指针中空闲的高位存储GC元数据。

ZGC的并发转移：ZGC可以在用户线程运行的同时移动对象。通过染色指针和读屏障，当用户线程访问已转移的对象时，读屏障自动更新指针指向新地址。

ShenandoahGC底层实现

Shenandoah的核心技术是Brooks Forwarding Pointer，每个对象头部多一个指针，指向自己（正常状态）或转发后的新对象（GC时）。

三大GC核心技术对比说明：

维度 G1 ZGC Shenandoah
核心技术 Remembered Set 染色指针 Brooks指针
STW阶段 初始标记/最终标记/筛选回收 标记开始/结束/转移开始 初始/最终标记
并发阶段 并发标记 并发标记/转移/重映射 并发标记/整理/清除
额外内存 RSet占5%~20% 染色指针无额外 每对象多1指针
转移方式 STW复制 并发转移 并发整理

第五部分 面试篇

一、JVM基础概念

Q1: JVM是什么？Java为什么可以跨平台？

JVM是Java虚拟机，是一台虚构的计算机，通过软件模拟实现。Java程序编译为字节码（.class），JVM负责将字节码解释或编译为对应平台的机器码执行。不同操作系统有不同的JVM实现，但它们都能运行相同的字节码，从而实现跨平台。

Q2: JVM由哪些部分组成？

JVM由三大子系统组成：

  1. 类加载子系统：负责加载字节码到内存
  2. 运行时数据区：包括程序计数器、Java栈、本地方法栈、堆、方法区
  3. 执行引擎：包括解释器、JIT编译器、垃圾回收器

Q3: JDK、JRE、JVM的区别？

  • JDK = JRE + 开发工具（javac、javadoc等）
  • JRE = JVM + 核心类库
  • JVM = 虚拟机，运行字节码

Q4: 解释执行和编译执行有什么区别？

  • 解释执行：逐行解释字节码，启动快，执行慢
  • 编译执行（JIT）：将热点代码编译为机器码，启动慢，执行快
  • HotSpot采用混合模式：先解释执行，热点代码由JIT编译后直接执行

二、字节码文件结构

Q5: class文件的结构是什么？

class文件以魔数0xCAFEBABE开头，依次包含：版本号、常量池、访问标志、类/父类/接口信息、字段表、方法表、属性表。常量池是核心，存放字面量和符号引用。

Q6: 如何查看字节码？

使用javap命令：javap -c -v ClassName，或使用IDEA的JClassLib插件。通过字节码可以理解JVM执行逻辑、排查框架原理、分析性能问题。

三、运行时数据区内存溢出场景

Q7: 哪些区域会发生OOM？哪些不会？

区域 是否会OOM 原因
程序计数器 不会 固定大小，仅记录行号
Java栈 会（StackOverflowError） 递归过深或栈帧过大
本地方法栈 会（StackOverflowError） 同Java栈
堆 会（OutOfMemoryError） 对象过多或过大
方法区 会（OutOfMemoryError） 加载类过多
直接内存 会（OutOfMemoryError） NIO分配过多

四、类完整生命周期

Q8: 描述类的完整生命周期。

类的生命周期包括七个阶段：

  1. 加载：获取字节流，放入方法区，生成Class对象
  2. 验证：检查字节码合法性
  3. 准备：为静态变量分配内存并设零值
  4. 解析：符号引用替换为直接引用
  5. 初始化：执行<clinit>方法，静态变量赋值和静态代码块
  6. 使用：正常使用类
  7. 卸载：从JVM中卸载

其中2~4合称连接阶段。

Q9: 哪些情况会触发类初始化？哪些不会？

会触发：

  • new实例化对象
  • 访问静态变量（非final）
  • 调用静态方法
  • 反射（Class.forName）
  • 初始化子类时父类先初始化
  • main方法所在的类

不会触发：

  • 通过子类引用父类静态变量
  • 通过数组定义引用
  • 引用final常量
  • 类名.class

五、类加载器 + 双亲委派机制，如何打破

Q10: 双亲委派模型是什么？为什么需要？

类加载器收到加载请求时，先委托给父加载器，父加载器无法加载时自己才加载。好处：

  • 安全性：防止核心类被篡改
  • 唯一性：保证类不会被重复加载

Q11: 如何打破双亲委派？有哪些实际应用？

三种方式：

  1. 自定义类加载器，重写loadClass方法
  2. 线程上下文类加载器（SPI机制）
  3. OSGi模块化类加载

实际应用：

  • JDBC的Driver SPI加载
  • Tomcat的Web应用隔离
  • 热部署框架

六、Tomcat自定义类加载器

Q12: Tomcat为什么需要自定义类加载器？

Tomcat作为Web容器，需要支持多个Web应用共存，每个应用使用不同版本的库，必须实现类隔离。

Tomcat打破了双亲委派，WebAppClassLoader会先自己加载，而非先委托父加载器。这样不同应用可以加载同一个类库的不同版本。

七、对象四大引用类型

Q13: 四种引用的区别和用途？

引用 回收时机 典型应用
强引用 永不回收 普通对象
软引用 内存不足时 缓存（图片缓存）
弱引用 下次GC时 ThreadLocal、WeakHashMap

八、GC回收算法

Q14: 三种基本GC算法的原理和优缺点？

算法 原理 优点 缺点 适用
标记清除 标记存活，清除未标记 简单 碎片 老年代
标记复制 存活对象复制到另一区 无碎片 浪费空间 新生代
标记整理 存活对象向一端移动 无碎片 移动开销 老年代

Q15: 分代GC策略是什么？

将堆分为新生代（Eden + S0 + S1）和老年代，新生代对象存活少用复制算法，老年代存活多用标记清除/整理算法。对象先在Eden分配，经过多次Minor GC存活后晋升老年代。

九、内存泄漏排查思路

Q16: 线上内存泄漏如何排查？

  1. 监控告警：发现内存持续增长或频繁Full GC
  2. 导出堆快照：jmap -dump:format=b,file=heap.hprof <pid>
  3. MAT分析：查看Leak Suspects、Dominator Tree、Path to GC Roots
  4. 定位代码：找到引用链，定位泄漏对象创建位置
  5. 修复验证：修复后重新部署，观察GC日志确认

Q17: 常见的内存泄漏场景有哪些？

  • 静态集合持有对象引用
  • 资源未关闭（InputStream、Connection）
  • ThreadLocal未remove
  • 监听器/回调未注销
  • 缓存无过期策略
  • 内部类持有外部类引用
