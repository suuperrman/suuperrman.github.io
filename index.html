JavaSE学习笔记

第一章 Java概述

1.1 Java发展史

Java由Sun Microsystems公司于1995年正式发布，创始人为James Gosling。最初命名为Oak（橡树），后更名为Java。发展历程中的重要节点：

  • 1995年：JDK 1.0发布，提出”Write Once, Run Anywhere”理念
  • 1998年：JDK 1.2发布，Java分为J2SE、J2EE、J2ME三大平台
  • 2004年：JDK 5.0发布，引入泛型、枚举、注解等重大特性
  • 2009年：Oracle收购Sun Microsystems
  • 2014年：Java 8发布，引入Lambda、Stream API等革命性特性
  • 2017年：Java 9发布，引入模块化系统（JPMS）
  • 2018年起：改为每6个月发布一个版本（Java 10, 11, 12…）
  • 当前LTS版本：Java 8、11、17、21

1.2 JDK与JRE

JDK（Java Development Kit，Java开发工具包）

JDK是Java开发的核心，包含了编译器（javac）、运行时环境（JRE）、核心类库（rt.jar / modules）以及各种开发工具（javadoc、jdb、jar等）。程序员编写Java源代码后，需要JDK来编译和运行程序。

JRE（Java Runtime Environment，Java运行环境）

JRE是Java程序运行的最小环境，包含JVM（Java虚拟机）和核心类库。如果只需要运行Java程序而不需要开发，则安装JRE即可。

区别与联系

维度 JDK JRE
包含关系 JDK包含JRE JRE是JDK的子集
主要功能 编译 + 运行 仅运行
目标用户 开发者 终端用户
核心工具 javac, jar, javadoc等 java命令

JDK = JRE + 开发工具；JRE = JVM + 核心类库。

1.3 跨平台原理（JVM）

Java的跨平台特性依赖于JVM。Java源代码（.java）经过编译后生成字节码文件（.class），字节码不依赖于任何特定操作系统，由各个平台上的JVM负责解释执行。不同操作系统有各自对应的JVM实现，但所有JVM都能识别相同的字节码格式，从而实现”一次编译，到处运行”。

注意事项：JVM本身不是跨平台的，不同操作系统需要安装对应版本的JVM。跨平台的是字节码文件，而非JVM本身。

1.4 Java五大特性

  1. 简单性：基于C++简化而来，去除了指针、多继承、运算符重载等复杂特性，提供自动垃圾回收机制。
  2. 面向对象：一切皆对象，支持封装、继承、多态、抽象四大OOP特性，围绕类和对象组织代码。
  3. 分布式：提供丰富的网络编程API（Socket、RMI等），支持构建分布式应用，可方便地访问远程资源。
  4. 健壮性：强类型机制、异常处理机制、自动垃圾回收，共同保障了程序的稳定运行。
  5. 安全性：取消了指针操作，提供字节码验证、类加载机制、安全管理器等多层安全防护。

第二章 面向对象（OOP）

2.1 类与对象

类的定义

类是对象的模板或蓝图，描述了具有相同属性和行为的一组对象的抽象。类由成员变量（属性/状态）和成员方法（行为）组成。

对象的创建与使用

对象是类的具体实例，通过new关键字创建。使用对象名.属性或对象名.方法()访问成员。

注意事项：多个对象之间内存独立，修改一个对象的属性不会影响另一个对象的属性。

2.2 三大特性

2.2.1 封装

封装是将对象的属性和实现细节隐藏起来，仅对外暴露必要的访问接口，提高代码安全性和可维护性。

访问修饰符

修饰符 本类 同包 子类 其他包
private 可访问 不可 不可 不可
default（无修饰符） 可访问 可访问 不可 不可
protected 可访问 可访问 可访问 不可
public 可访问 可访问 可访问 可访问

getter/setter方法

使用场景：所有实体类、数据模型都应使用封装，将属性私有化并提供getter/setter。

注意事项：布尔类型的getter方法通常命名为isXxx()而非getXxx()。

2.2.2 继承

继承是子类继承父类的属性和方法，实现代码复用和层次化设计。Java中只支持单继承（一个类只能有一个直接父类），但支持多层继承。

extends关键字

super关键字

super代表父类对象的引用，用于：

  • 调用父类构造方法：super(参数)
  • 调用父类被重写的方法：super.方法名()
  • 访问父类被隐藏的成员变量：super.变量名

注意事项：子类构造方法默认会调用父类的无参构造方法（super()），如果父类没有无参构造方法，则子类必须显式调用父类的有参构造方法。

方法重写（Override）

子类定义与父类方法签名完全相同的方法，以提供自己的实现。重写发生在父子类之间，是运行时多态的基础。

重写规则：

  • 方法名、参数列表必须完全相同
  • 返回类型可以是父类返回类型的子类型（协变返回类型）
  • 访问修饰符不能比父类更严格（可以更宽松）
  • 不能重写private、static、final方法
  • 抛出异常不能比父类更宽泛

2.2.3 多态

多态是指同一操作作用于不同对象时，可以产生不同的执行结果。Java中多态分为编译时多态和运行时多态。

编译时多态（方法重载 Overload）

同一个类中，方法名相同但参数列表不同（个数、类型、顺序不同），与返回值类型无关。

运行时多态（向上转型）

父类引用指向子类对象，在运行时根据实际对象类型调用对应的方法。

使用场景：面向接口编程、策略模式、工厂模式等设计模式的实现基础。

注意事项：

  • 向上转型是安全的，自动进行
  • 向下转型需要强制转换，必须先使用instanceof判断，否则可能抛出ClassCastException
  • 成员变量没有多态性，编译看左边，运行看左边
  • 成员方法有多态性，编译看左边，运行看右边
  • 静态方法没有多态性

重载 vs 重写对比说明：

维度 重载（Overload） 重写（Override）
发生位置 同一个类中 父子类之间
方法签名 方法名相同，参数列表不同 方法名相同，参数列表相同
返回类型 可以不同 相同或子类型
访问修饰符 无限制 不能更严格
多态类型 编译时多态 运行时多态
绑定时机 编译期绑定 运行期绑定

2.3 抽象类与接口

抽象类（abstract）

抽象类是不能被实例化的类，用于定义抽象模板，子类必须实现其抽象方法。

接口（interface）

接口是更纯粹的抽象，定义了一组规范（行为契约），实现类必须遵守。Java 8起接口可以包含默认方法和静态方法。

多实现与多继承

Java中类只能单继承，但可以实现多个接口，弥补了单继承的不足。

抽象类 vs 接口对比说明：

维度 抽象类 接口
关键字 abstract class interface
继承/实现 单继承 多实现
构造方法 可以有 没有
成员变量 可以是普通变量 只能是public static final常量
方法 可以有抽象方法和普通方法 抽象方法、default方法、static方法
设计理念 is-a关系（模板） can-do关系（契约/能力）
使用场景 有共同基类、部分实现可复用 定义行为规范、解耦

2.4 构造器

构造器（构造方法）是创建对象时自动调用的特殊方法，用于初始化对象。构造方法名与类名相同，没有返回类型（void也不能写）。

注意事项：

  • this()调用同类构造方法，super()调用父类构造方法
  • this()和super()都必须放在构造方法的第一行，因此不能同时出现
  • 如果父类没有无参构造方法，子类必须显式调用父类的有参构造方法

2.5 代码块

执行顺序：静态代码块 > 构造代码块 > 构造方法。静态代码块只执行一次，构造代码块每次创建对象都执行。

2.6 内部类

内部类是定义在另一个类内部的类，可以访问外部类的私有成员。

使用场景：

  • 成员内部类：当内部类与外部类紧密关联时使用
  • 静态内部类：内部类不需要依赖外部类实例时使用
  • 局部内部类：只在某个方法中使用的临时类
  • 匿名内部类：简化代码，常用于事件监听、线程创建等场景

2.7 对象间四种关系

  • 依赖（Dependency）：A类的方法使用了B类对象（参数、局部变量），是最弱的关系。例如：方法参数传入一个对象。
  • 关联（Association）：A类持有B类的引用作为成员变量，表示一种长期的关系。例如：学生和课程的关系。
  • 聚合（Aggregation）：整体与部分的关系，但部分可以脱离整体独立存在。例如：球队和球员，球员离开球队仍然存在。
  • 组合（Composition）：更强的整体与部分关系，部分不能脱离整体独立存在。例如：人和心脏，人死了心脏也没意义了。

2.8 包与导入

注意事项：java.lang包下的类自动导入，不需要手动import。避免使用通配符导入，可能导致命名冲突。

4.1 Object类

Object是所有类的根类，Java中每个类都直接或间接继承自Object。

equals()方法

默认比较对象的内存地址（等同于==），通常需要重写来自定义相等逻辑。

equals() vs == 对比说明：

维度 == equals()
比较内容 基本类型比较值，引用类型比较地址 默认比较地址，可重写比较内容
能否重写 不能（运算符） 可以
适用场景 基本类型比较、判断是否为同一对象 比较对象内容是否相同

hashCode()方法

返回对象的哈希码值，用于HashMap、HashSet等哈希表结构。重写equals时必须同时重写hashCode，保证相等对象的hashCode一定相等。

约定：

  • 如果a.equals(b)为true，则a.hashCode() == b.hashCode()
  • 如果a.hashCode() == b.hashCode()，a和b不一定equals（哈希冲突）
  • 多次调用同一对象的hashCode应返回相同值

toString()方法

返回对象的字符串表示，默认格式为类名@十六进制哈希码。通常重写以返回有意义的对象信息。

clone()方法

创建对象的副本。需要实现Cloneable接口并重写clone()方法，否则抛出CloneNotSupportedException。

浅拷贝 vs 深拷贝：浅拷贝只复制对象本身，引用类型字段仍指向原对象；深拷贝会将引用类型字段也复制一份。实现深拷贝通常需要序列化或手动递归复制。

finalize()方法

对象被GC回收前调用，Java 9起已标记为废弃，不推荐使用。因为其执行时机不确定，可能导致性能问题。

第七章 泛型

7.1 泛型概述

泛型是Java 5引入的类型参数化机制，允许在定义类、接口、方法时使用类型参数，在编译时进行类型检查，避免运行时ClassCastException。

使用场景：集合框架中的类型约束、通用工具类的编写、编译期类型安全检查。

7.2 泛型类

7.3 泛型接口

7.4 泛型方法

泛型方法独立于泛型类，可以在普通类中定义泛型方法。

7.5 类型通配符

PECS原则（Producer Extends, Consumer Super）：

  • 如果泛型只用于读取（生产者），使用? extends T
  • 如果泛型只用于写入（消费者），使用? super T
  • 如果既读又写，使用具体类型参数T

7.6 泛型擦除

Java的泛型是编译时机制，编译后类型参数会被擦除，替换为边界类型（默认Object）。这是为了向后兼容Java 5之前的代码。

注意事项：

  • 泛型类型不能是基本类型（如List<int>），必须使用包装类（List<Integer>）
  • 不能创建泛型数组（new T[10]）
  • 不能在静态字段或方法中引用类的类型参数
  • 不能对泛型类型使用instanceof

第十一章 NIO

11.1 NIO概述

NIO（New IO / Non-blocking IO）是Java 1.4引入的IO模型，核心组件为Channel（通道）、Buffer（缓冲区）和Selector（选择器）。与传统IO相比，NIO是面向缓冲区、非阻塞的IO操作。

传统IO vs NIO 对比说明：

维度 传统IO（BIO） NIO
数据流向 面向流（单向） 面向通道（双向）
数据处理 逐个字节处理 面向缓冲区（块处理）
阻塞模式 阻塞 非阻塞
适用场景 连接数少、数据量大的场景 连接数多、数据量小的场景

11.2 Buffer（缓冲区）

Buffer是NIO中数据的容器，本质上是一块可读写的内存区域。

Buffer核心属性：

  • capacity：缓冲区容量，创建后不可变
  • position：当前读写位置
  • limit：可读写数据的边界
  • mark：标记位置，可通过reset()回到此位置

11.3 Channel（通道）

Channel是双向的数据传输通道，可以同时读写。

11.4 Selector（选择器）

Selector是NIO多路复用的核心，一个线程可以管理多个Channel。Selector只适用于网络Channel（SocketChannel、ServerSocketChannel），不能用于FileChannel。

11.6 异步文件通道

Java 7引入的AsynchronousFileChannel支持异步文件操作。

第十二章 多线程与并发

12.1 线程五种状态

Java线程的生命周期包含以下五种状态：

  1. 新建（New）：创建Thread对象但尚未调用start()
  2. 就绪（Runnable）：调用start()后，等待CPU调度
  3. 运行（Running）：获得CPU时间片，执行run()方法
  4. 阻塞（Blocked）：线程被挂起，等待某个条件满足
    • 等待阻塞：调用wait()，等待notify()唤醒
    • 同步阻塞：等待获取synchronized锁
    • 其他阻塞：调用sleep()或join()
  5. 死亡（Dead）：run()方法执行完毕或异常退出

12.2 创建线程

方式一：继承Thread类

方式二：实现Runnable接口（推荐）

方式三：实现Callable接口（有返回值）

三种创建方式对比说明：

维度 继承Thread 实现Runnable 实现Callable
返回值 无 无 有（Future接收）
异常处理 不能抛出checked异常 不能抛出checked异常 可以抛出异常
资源复用 类与任务耦合 任务与线程分离，可复用 任务与线程分离
局限性 单继承限制 无 相对复杂

12.3 线程控制

sleep vs wait vs yield vs join 对比说明：

方法 作用 释放锁 使用场景
sleep() 让线程休眠指定时间 不释放 延时操作
wait() 让线程等待，直到被唤醒 释放锁 线程间通信
yield() 让出CPU执行权 不释放 调试/测试
join() 等待目标线程执行完毕 不释放 线程顺序执行

synchronized vs Lock 对比说明：

维度 synchronized Lock
类型 关键字（JVM层面） 接口（API层面）

性能 JDK6+优化后性能相近 高竞争下略优

死锁

死锁是指两个或多个线程互相持有对方需要的锁，导致所有线程都无法继续执行。

死锁产生的四个必要条件（缺一不可）：

  1. 互斥条件：资源不能被多个线程共享
  2. 持有并等待：线程持有资源的同时等待其他资源
  3. 不可剥夺：线程持有的资源不能被强制剥夺
  4. 循环等待：多个线程形成循环等待链

预防死锁：破坏上述任一条件即可。最常用的方法是统一加锁顺序（破坏循环等待条件）。

保证原子性 否（复合操作不安全） 是
禁止指令重排 是 是
性能开销 低 较高
使用场景 状态标志、DCL单例 需要原子性保证的复合操作

12.5 线程通信

wait() / notify() / notifyAll()

注意事项：

  • wait()、notify()、notifyAll()必须在synchronized块中调用，否则抛出IllegalMonitorStateException
  • wait()应该用while循环检查条件，而非if，防止虚假唤醒
  • notify()随机唤醒一个等待线程，notifyAll()唤醒所有

四种拒绝策略：

  • AbortPolicy（默认）：抛出RejectedExecutionException
  • CallerRunsPolicy：由调用者线程执行任务
  • DiscardPolicy：直接丢弃新任务
  • DiscardOldestPolicy：丢弃队列中最旧的任务

注意事项：生产环境中禁止使用Executors创建线程池，因为其默认队列无界或线程数无界，可能导致OOM。应使用ThreadPoolExecutor手动指定参数。

Atomic原子类

CAS机制：Compare And Swap（比较并交换），是CPU级别的原子指令。CAS操作包含三个操作数：内存位置（V）、预期原值（A）、新值（B）。如果V的值等于A，则将V更新为B，否则不做任何操作。CAS操作由Unsafe类提供底层支持。

CAS的ABA问题：一个值从A变为B再变回A，CAS无法检测到变化。解决方案是使用版本号（AtomicStampedReference）或标记（AtomicMarkableReference）。

13.5 setAccessible（暴力访问）

setAccessible(true)可以绕过Java的访问权限检查，访问私有成员。这是反射强大能力的来源，也是安全风险所在。

注意事项：

  • JDK 9+模块化系统对反射有更严格的限制，未开放的模块无法通过反射访问
  • 从JDK 17开始，setAccessible的使用受到更严格限制
  • 在高版本JDK中，可能需要添加--add-opensJVM参数来允许反射访问

13.6 反射应用场景

  • Spring框架：依赖注入（@Autowired）、Bean实例化、AOP代理
  • 动态代理：JDK动态代理依赖反射调用目标方法
  • ORM框架：实体类与数据库表的映射
  • 序列化框架：通过反射获取和设置对象属性
  • 单元测试：JUnit通过反射调用测试方法
  • IDE功能：代码补全、类结构分析

性能注意事项：反射调用比直接调用慢，因为需要安全检查、类型解析等额外开销。高频调用的场景建议使用setAccessible(true)并缓存Method/Field对象，或使用MethodHandle（Java 7+）或LambdaMetafactory（Java 8+）替代。

第十四章 动态代理

14.1 动态代理概述

动态代理是在运行时动态生成代理类的技术，无需手动编写代理类。主要用于AOP（面向切面编程）、RPC框架、事务管理、日志记录等场景。

14.2 JDK动态代理

JDK动态代理基于接口实现，使用java.lang.reflect.Proxy和InvocationHandler。目标类必须实现至少一个接口。

JDK动态代理原理：Proxy.newProxyInstance()在运行时动态生成一个实现了所有指定接口的代理类字节码，该类将所有方法调用转发给InvocationHandler.invoke()。

14.3 CGLIB动态代理

CGLIB（Code Generation Library）基于继承实现，可以代理没有实现接口的类。通过ASM字节码技术生成目标类的子类，重写父类方法实现代理。

JDK动态代理 vs CGLIB动态代理 对比说明：

维度 JDK动态代理 CGLIB动态代理
原理 基于接口 基于继承（生成子类）
要求 目标类必须实现接口 目标类不能是final（方法不能是final）
性能 创建代理快，调用略慢 创建代理慢，调用略快
内部实现 反射调用 生成字节码直接调用
使用场景 接口代理 无接口类的代理

第十六章 JVM内存结构

16.1 运行时数据区域

JVM运行时数据区域分为以下五个部分：

堆（Heap）

堆是JVM中最大的一块内存区域，所有线程共享，在虚拟机启动时创建。用于存储对象实例和数组，是垃圾回收的主要区域。

堆内存结构（分代模型，JDK 8及之前）：

  • 新生代（Young Generation）：Eden区 + 两个Survivor区（S0, S1），存放新创建的对象
  • 老年代（Old Generation）：存放生命周期较长的对象
  • JDK 8中永久代被元空间（Metaspace）替代，使用直接内存

栈（Stack）

每个线程拥有独立的虚拟机栈，每个方法执行时创建一个栈帧（Stack Frame），存储局部变量表、操作数栈、动态链接、方法返回地址等。

栈溢出：递归调用过深或方法局部变量过多时抛出StackOverflowError。

方法区（Method Area）

所有线程共享，存储已被虚拟机加载的类信息、常量、静态变量、即时编译后的代码缓存等。JDK 8中方法区由元空间（Metaspace）实现，使用直接内存（不再受限于JVM的-XX:MaxPermSize）。

程序计数器（Program Counter Register）

每个线程独有，是一块较小的内存空间，记录当前线程所执行的字节码行号。分支、循环、跳转、异常处理、线程恢复等依赖程序计数器。此区域不会发生OOM。

本地方法栈（Native Method Stack）

每个线程独有，为虚拟机使用到的本地方法（Native方法，用C/C++编写）服务。

16.2 类加载机制

类的生命周期：加载 -> 验证 -> 准备 -> 解析 -> 初始化 -> 使用 -> 卸载

  1. 加载：通过类的全限定名获取二进制字节流，将字节流转换为方法区运行时的数据结构，在堆中生成Class对象
  2. 验证：确保Class文件字节流符合JVM规范（文件格式、元数据、字节码、符号引用验证）
  3. 准备：为静态变量分配内存并设置零值（final static常量直接赋初始值）
  4. 解析：将常量池中的符号引用替换为直接引用
  5. 初始化：执行类构造器<clinit>()方法，初始化静态变量和静态代码块

16.3 类加载器

类加载器负责将类的字节码加载到JVM中。Java采用双亲委派模型。

双亲委派模型：类加载器收到加载请求时，先委托给父类加载器，父类加载器无法加载时才自己加载。这种机制保证了Java核心类库的安全性（防止自定义类覆盖核心类）。

自定义类加载器：继承ClassLoader类，重写findClass()方法。

16.4 垃圾回收（GC）

可达性分析

JVM通过可达性分析判断对象是否存活。以GC Roots为起点，从这些节点向下搜索，走过的路径称为引用链。引用链不可达的对象被判定为可回收。

GC Roots包括：

  • 虚拟机栈中引用的对象
  • 静态属性引用的对象
  • 常量引用的对象
  • 本地方法栈中引用的对象
  • 被同步锁（synchronized）持有的对象

引用类型

垃圾回收算法

算法 描述 优点 缺点
标记-清除 标记存活对象，清除未标记对象 简单 产生内存碎片
标记-复制 将存活对象复制到另一块内存 无碎片，效率高 浪费一半内存
标记-整理 标记后将存活对象向一端移动 无碎片 移动对象开销大

分代收集策略：

  • 新生代：使用标记-复制算法（Minor GC，频繁）
  • 老年代：使用标记-清除或标记-整理算法（Major GC / Full GC，较少）

  • 不要手动调用System.gc()，让JVM自行决定GC时机
  • 工作中关注GC频率和Full GC时间，使用jstat、GC日志等工具监控
  • 避免创建大量短生命周期的大对象，会频繁触发GC
